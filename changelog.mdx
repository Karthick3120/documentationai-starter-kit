## Release Summary

The latest entries show how to organize your documentation history into clear sections. You can use this structure to highlight releases, capture fixes, and communicate ongoing improvements.

### What to include

- New features that users can try right away
- Improvements that make the experience smoother
- Bug fixes that resolve documented issues
- Version numbers that reflect your release process

### Suggested release workflow

<Steps>
  <Step title="Collect changes" icon="clipboard">
    Gather updates from your roadmap, issue tracker, or team notes before writing the release entry.
  </Step>
  <Step title="Group by type" icon="layers">
    Organize content into New Features, Improvements, and Bug Fixes so readers can scan quickly.
  </Step>
  <Step title="Publish and review" icon="check-circle">
    Review wording, confirm dates, and publish the changelog alongside your documentation update.
  </Step>
</Steps>

## Writing Patterns

Use the same style for every release so your changelog stays easy to read. Short bullets work best, especially when you want readers to understand progress in a few seconds.

## Versioning Guide

<Tabs>
  <Tab title="Major releases" icon="rocket">

Use major releases when you make large changes to structure, behavior, or long-term direction.

  </Tab>
  <Tab title="Minor releases" icon="zap">

Use minor releases when you add useful features, improve usability, or expand existing content.

  </Tab>
  <Tab title="Patch releases" icon="shield">

Use patch releases when you fix bugs, correct copy, or make small documentation improvements.

  </Tab>
</Tabs>
