## Create your workspace

A documentation workspace is the place where you collect pages, drafts, and shared guidance. You can think of it as the home base for your content system. Keep the first version small and focused so it is easy to maintain.

### What to prepare

Before you write, decide on three basics:

- A workspace name that matches your project
- A primary audience for the content
- A small set of starter pages that cover the most important topics

### Setup checklist

<Steps>
  <Step title="Choose a workspace name" icon="bookmark">
    Pick a name that is short, recognizable, and easy to reuse across pages, navigation, and search.
  </Step>
  <Step title="Define your first sections" icon="layout-grid">
    Create a simple structure such as Overview, Setup, Usage, and Troubleshooting.
  </Step>
  <Step title="Add your first draft page" icon="file-text">
    Write one page first so you can validate the tone, structure, and publishing flow.
  </Step>
  <Step title="Review and publish" icon="check-circle">
    Confirm links, headings, and formatting before you share the page with others.
  </Step>
</Steps>

## Add and structure pages

A good documentation structure helps readers find answers quickly. Start with a single home page, then add supporting pages as your content expands. Keep headings clear and predictable so readers can scan the page without effort.

<Tabs>
  <Tab title="Simple structure" icon="book-open">

A simple structure works well for a new workspace:

- Home
- Quickstart
- How it works
- FAQ

This layout keeps navigation lightweight and easy to understand.

  </Tab>
  <Tab title="Team structure" icon="users">

A team structure works well when multiple people contribute:

- Overview
- Setup
- Guides
- Policies
- Changelog

This layout gives each contributor a clear place to publish.

  </Tab>
  <Tab title="Product structure" icon="layers">

A product structure works well when you need role-based content:

- Getting started
- Configuration
- Reference
- Release notes
- Support

This layout scales as your documentation becomes more detailed.

  </Tab>
</Tabs>

### Example page outline

Use a repeatable outline for each new page:

1. Explain the goal.
2. Show the main workflow.
3. Add an example.
4. Close with the next action.

This pattern keeps pages consistent and reduces confusion for readers who jump between topics.

## Publish your first page

Publishing should feel routine, not risky. Write the content, review the structure, and then push it live when it is ready. Keep the first publish simple so you can learn the workflow before adding more complexity.

<CodeGroup tabs="Markdown,JSON" show-lines={true}>
  ```markdown
  ## Getting started

  You can create a page with a clear title, a short summary, and a few practical steps.

  ### Recommended sections

  - What this page covers
  - How to use it
  - What to do next
  ```

  ```json
  {
    "title": "Getting started",
    "status": "draft",
    "topics": ["setup", "workflow", "publish"]
  }
  ```
</CodeGroup>

### Basic publishing flow

1. Write the page in your editor.
2. Check the headings and links.
3. Preview the page locally.
4. Publish when the content reads clearly.

<Callout kind="tip">

If you expect frequent edits, keep the first version short. Short pages are easier to review, update, and translate into new topics later.

</Callout>

## Workspace setup essentials

Your first workspace should be easy to understand and easy to maintain. Focus on naming, navigation, and content ownership before you add advanced features.

### Recommended defaults

| Area | Recommendation |
|------|----------------|
| Page titles | Use clear, direct names |
| Navigation | Keep the first menu small |
| Drafts | Store work-in-progress in one place |
| Review | Check content before publishing |
| Updates | Revisit pages regularly |

### Good starting habits

- Keep one idea per page when possible.
- Use short introductions and clear subheadings.
- Link related pages together.
- Review old pages before adding new ones.
- Replace temporary wording with final copy as soon as you can.

## Next steps

Once you have a first page published, you can expand your workspace with guides, references, and FAQs. Keep building in small increments so each addition improves the reading experience.

<Expandable title="What should you add next?" default-open="false">
